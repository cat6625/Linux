# Redmi 10（5年）vs Redmi Note 15 5G（全新）待機耗電測試

## 一、測試前準備（兩部機都做）

```bash
# 1. 確認手機狀態
adb shell dumpsys battery | grep -E "level|health|Charge counter|voltage|temperature"
adb shell cat /sys/class/power_supply/battery/cycle_count 2>/dev/null   # 部分機型有

# 2. 充滿電到 100%，拔掉充電器
# 3. 關閉行動網路，只留 Wi-Fi 連同一個 AP
# 4. 飛航模式關閉，藍牙關閉，定位關閉
# 5. 螢幕關閉前先鎖定桌面（避免第三方 Launcher 差異）
```

## 二、建議測試時長

| 裝置 | 建議時長 | 原因 |
|------|----------|------|
| Redmi 10（5年） | 6–8 小時 | 電池老化，曲線可能非線性，需要長時間平均 |
| Redmi Note 15 5G | 4–6 小時 | 新電池，短時間即可看出基線 |

**兩部同時開始、同時結束**，方便對比。

## 三、執行測試

```bash
# 兩部機各自找出無線除錯 Port 後執行
~/doze-tools/doze.sh <port> --reset-batterystats

# 步驟：
# 1. 出現 "Next wake from idle" → 輸入 y
# 2. 出現 "輸入 RESET" → 輸入 RESET
# 3. 腳本送 KEYCODE_SLEEP 後，放著不管
# 4. 等夠時間後，回到 Termux 按 Enter
```

**不要中途亮屏、不要插電、不要開熱點。**

## 四、判讀重點（按順序看）

### 1. 先看「電池快照對比」

```
- 快照覆蓋時長：Xh Ym
- 電量變化：A% → B%（下降 N%）
```

- 若 `下降 N%` 為 0 → 測試太短或電量被平滑，**數據不可用**，重做
- Redmi 10 若要看到 5–10% 下降，通常需 6 小時以上

### 2. 再看「Estimated power use」的 actual drain

```
Computed drain: XXX, actual drain: YYY-ZZZ
```

- **Redmi 10**：若 `ZZZ / XXX ≥ 5` → 高度懷疑電池老化
  - 交叉驗證：`dumpsys battery | grep health` 若顯示 `Overheat` 或 `Dead` 就確認
  - 也可看 `Charge counter` 與 `level` 反推實際容量
- **Redmi Note 15 5G**：若 `ZZZ / XXX` 在 1.5–2.5 倍 → **正常**（BatteryStats 模型本來就低估）

### 3. 對比「Deep idle」與「CPU suspend」

| 指標 | Redmi 10 預期 | Redmi Note 15 5G 預期 |
|------|---------------|------------------------|
| Deep idle 佔比 | > 90%（若 < 85% 表示頻繁離開） | > 95% |
| CPU suspend | > 90% | > 95% |
| Wi-Fi kernel active | 可能偏高（舊 Wi-Fi 晶片省電差） | < 30% |

### 4. 看「Partial Wakelock 前 8 名」

新機應該只有：
- `deviceidle_maint`（system，Doze 維護，正常）
- `gms_scheduler`（GMS 排程，正常）
- `AnyMotionDetector`（動作偵測，正常）

舊機若出現大量第三方 App 的 job/wakelock，代表背景活動沒被有效限制。

### 5. 看「放電曲線」的突發區段

- 舊機如果出現多段 `⚠ 疑似突發耗電區段` → 電池內阻升高，電壓瞬間掉落被誤判為「放電」
- 新機若出現 → 真的有 App 在背景搞事

## 五、兩部機對比時的三個注意事項

### ⚠️ 1. 設計容量不同，不能直接比 mAh

- Redmi 10：`Capacity: 5415`
- Redmi Note 15 5G：`Capacity: 5000`

要比的話，換算成 **% / 小時**：

```
每小時掉電 % = (起點% − 終點%) / 測試小時數
```

例：Redmi 10 若 6 小時掉 8% → 1.33%/h；Note 15 若 6 小時掉 3% → 0.5%/h。

### ⚠️ 2. 系統版本不同，BatteryStats 行為不同

Redmi 10 是舊 MIUI，powerkeeper 可能更積極干擾；Note 15 是新 HyperOS，統計可能更準。**不要用「Computed drain 數字」直接比兩台**，要比的是「actual drain / 設計容量」這個比例。

### ⚠️ 3. 5 年電池的健康度是最大變數

紅米 10 若循環次數 > 800，實際容量可能只剩 60–70%（約 3200–3800 mAh）。這會讓：
- `actual drain` 被高估（用設計容量算，但實際容量小）
- `Discharge` 看起來正常，但實際掉 % 很快

**判讀 Redmi 10 的數據時，先把「actual drain 與 Computed drain 的倍率」當成電池健康度的間接指標**，而不是耗電元兇。

| 項目 | Redmi 10 | Redmi Note 15 5G |
|------|----------|-------------------|
| 測試時長 | ___ h | ___ h |
| 電量變化 | __% → __% | __% → __% |
| 每小時掉電 | ___ %/h | ___ %/h |
| Deep idle 佔比 | ___% | ___% |
| CPU suspend | ___% | ___% |

| actual drain | ___–___ mAh | ___–___ mAh |

| 電池健康度推測 | 老化 / 正常 | 正常 |

**結論判準**：
- Redmi 10 `actual / computed ≥ 5` 且 `每小時掉電 > 1.5%/h` → 電池老化為主因，換電池可望改善 50% 以上
- Redmi Note 15 5G `每小時掉電 < 0.5%/h` → 待機正常
- 若新機掉電反而比舊機快 → 檢查是否有新安裝的 App 在背景活躍（看 Partial Wakelock）
