# Android BatteryStats 電池統計數據深度分析報告

## 常用adb指令
> **📋🚀 擷取基本資料**
>
```text
dumpsys batterystats | awk '/Statistics since last charge:/{f=1} /CONNECTIVITY POWER SUMMARY START/{f=0} f'
```

> **📋🚀 擷取基本資料+功耗**
>
```text
dumpsys batterystats | awk '/Statistics since last charge:/{f=1} /All kernel wake locks:/{f=0} f'
```

> **📋🚀 擷取基本資料+功耗+唤醒**
>
```text
dumpsys batterystats | awk '/Statistics since last charge:/{flag=1}/All wakeup reasons:/{in_wakeup=1}flag{if(in_wakeup&&!/^ /&&!/All wakeup reasons:/){flag=0}else{print}}'
```

## 原始提問
```text
請幫我分析以下這段 Android 系統的 batterystats（電池統計數據）日誌檔。

1. 核心數據總覽與換算：
   - 估計電池總容量是多少 mAh？
   - 這次統計歷時多久？總共消耗多少 mAh？換算約扣除百分之幾的電量？
   - 螢幕開啟時間（SoT）與螢幕關閉（待機）時間各是多少？

2. 每小時耗電率（%/h）精算與評級：
   - 計算「螢幕開啟耗電率（%/h）」與「螢幕關閉待機耗電率（%/h）」。
   - 簡評這個耗電數據屬於「極佳、正常、還是偏高」？

3. 軟體與背景耗電黑手：
   - 點名背景活動最頻繁、最可能導致耗電的 App 或系統服務（如 com.google.android.gms），並解釋其可能行為。

4. 系統與硬體環境影響：
   - 檢查「訊號強度（Cellular Signal Strength）」、「Wi-Fi / 行動網路切換」對耗電的影響。
   - 檢查是否有異常的「GPS / 定位時間」或「感測器（Sensors）使用過度」。
```

## 分析結論摘要 
> 本次電池數據統計歷時約 **25.7 小時**，總消耗 **4,066 mAh**（約 **81%** 電量）。  
> 核心結論：本次耗電主因為 **長螢幕開啟時間（SoT 達 8 小時 44 分）** 搭配 **高頻率 LTE/LTE-CA 行動網路傳輸**，待機機制（Doze）運作極佳（螢幕關閉耗電僅約 **0.41%/h**），並無待機漏電、GPS 或 Sensor 異常過載問題。

## 2. 耗電率精算與評級

### 🔴 螢幕開啟耗電率 (Screen On Rate)
- **螢幕開啟時間**：8.743 小時 (8h 44m 34s)
- **螢幕開啟消耗電量**：3,715 mAh
- **平均電流**：$3715 \text{ mAh} \div 8.743 \text{ h} \approx 425 \text{ mA}$
- **每小時耗電率計算**：
  - **以標稱容量 (5,020 mAh) 計**：$425 \div 5020 \times 100\% \approx$ **8.47% / h**
  - **以實際容量 (4,400 mAh) 計**：$425 \div 4400 \times 100\% \approx$ **9.66% / h**
- **綜合評級**：🟡 **正常 ～ 稍高**
- **情境分析**：
  - Log 紀錄顯示螢幕亮度為 `dark 8h 44m 34s (100%)`。若實際環境包含 **5G/LTE CA、高刷新率、高效能 CPU/GPU 負載或影音串流**，耗電約 8.5%/h 屬於正常範圍；若僅為低亮度 Wi-Fi 純文字閱讀，則偏高。

### 🟢 螢幕關閉待機耗電率 (Screen Off Rate)
- **螢幕關閉時間**：16.992 小時 (16h 59m 32s)
- **螢幕關閉消耗電量**：351 mAh
- **平均電流**：$351 \text{ mAh} \div 16.992 \text{ h} \approx 20.65 \text{ mA}$
- **每小時耗電率計算**：
  - **以標稱容量 (5,020 mAh) 計**：$20.65 \div 5020 \times 100\% \approx$ **0.41% / h**
  - **以實際容量 (4,400 mAh) 計**：$20.65 \div 4400 \times 100\% \approx$ **0.47% / h**
- **綜合評級**：🟢 **極佳 ～ 正常偏優**
- **情境分析**：
  - 接近 17 小時的待機僅消耗約 7% 電量，無任何異常漏電現象。

### 📊 總耗電結構比例
$$\text{螢幕開啟耗電佔比} = \frac{3715 \text{ mAh}}{4066 \text{ mAh}} \approx 91.4\%$$
$$\text{螢幕關閉耗電佔比} = \frac{351 \text{ mAh}}{4066 \text{ mAh}} \approx 8.6\%$$
> **結論**：整天 **91.4% 的耗電皆發生於螢幕亮起使用期間**，待機耗電影響微乎其微。

### 🔍 主要 UID 行為深入剖析

1. **`u0a274`（重點疑點）**
   - **直接耗電**：`595 mAh` （CPU: 85.3, Wake: 0.0005, Radio: **510 mAh**, GPS: 0.0295）
   - **分析**：高達 **86%** 的直接耗電來自 **Cellular Radio（行動網路傳輸）**，非 CPU 運算。Smearing 分攤後高達 1,580 mAh（包含螢幕與系統共享硬體分攤）。
2. **`u0a182`**
   - **直接耗電**：`343 mAh` （CPU: 46.5, Wake: 0.38, Radio: **296 mAh**）
   - **分析**：同樣有 **86%** 的耗電來自 Radio，屬於頻繁發送網路請求的應用或服務。
3. **`u0a1176` 與 `u0a181`**
   - **耗電**：分別為 `182 mAh` 與 `174 mAh`。
   - **分析**：耗電結構均為 **Radio 主導**（占比 > 84%），Wi-Fi、GPS 與 Sensor 耗電幾乎為 0。
4. **`UID 1000` (Android System)**
   - **直接耗電**：`527 mAh` （CPU: **516 mAh**）
   - **分析**：屬於 Android Framework / System Server 的整體運算消耗。考慮到長達 8.75 小時的 SoT，此 CPU 消耗屬於正常系統維運範圍。

## 4. 硬體與環境影響分析

### 📡 1. 行動網路與訊號強度 (Cellular Signal)
- **訊號品質分佈**：
  - **Good (良好)**：15 小時 01 分 (**58.4%**)
  - **Great (優良)**：9 小時 57 分 (**38.7%**)
  - **Moderate (中等)**：44 分 45 秒 (**2.9%**)
  - **Poor (差)**：0.55 秒 (**< 0.1%**)
- **判讀**：Good + Great 占比高達 **97.1%**，訊號環境非常優良。
- **結論**：❌ **排除「因訊號差導致 Modem 提高功率搜訊而耗電」的可能性。**

### ⚙️ 2. Cellular Kernel Active 時間現象
- **Kernel Active 時間**：`12 小時 06 分` (佔總時間 **47.0%**)
- **LTE CA 啟用率**：`96.9%`
- **數據傳輸紀錄**：`Cellular Rx time: 3.298s` / `Tx time: 0`
- **分析**：Kernel active 長達 12 小時但 Rx/Tx 紀錄極低，反映出 Modem 長時間維持於 LTE 載波聚合 (CA) 的活躍/連線狀態，此為主要硬體耗電（788 mAh + 283 mAh = 1,071 mAh，約佔總耗電 26.3%）的原因。

### 📶 3. Wi-Fi 與網路切換
- **Wi-Fi 狀態**：幾乎全程處於 `Disconnected`（WiFi Active: 23.5s, 數據收發為 0 B）。
- **網路切換次數 (Connectivity changes)**：僅 **4 次**。
- **結論**：🟢 **無頻繁切換網路造成的耗電問題。**

### 📍 4. 定位 (GPS) 與感測器 (Sensors)
- **GPS 總使用時間**：約 5 分 40 秒（Poor: 5m 35s, Good: 5s）。
- **GPS / Sensor 耗電量**：各 App 分配的 GPS/Sensor 耗電均小於 `0.05 mAh`。
- **結論**：🟢 **GPS 與 Sensors 完全無異常耗電。**

### 🌙 5. 待機休眠 (Doze) 與 Wakelock 機制
- **Light Doze**：4 小時 39 分
- **Full Doze**：11 小時 18 分（Full Idle 時間佔比 **43.9%**，最長單次休眠 **3h 47m 45s**）
- **Wakelocks**：Full Wakelock 僅 19 分 20 秒，Partial Wakelock 僅 21 分 58 秒。
- **結論**：🟢 **Doze 機制運作非常完善，無異常 Wakelock 阻止 CPU 休眠。**

## 5. 總結與續追建議

### 📌 核心總結
1. **健康度與待機**：這台手機**沒有待機漏電問題**。待機耗電僅約 **0.41%/h**，Doze 深度休眠機制正常。
2. **耗電主因**：高達 81% 的電量消耗，主要來自 **8 小時 44 分鐘的長螢幕開啟使用**，以及全程依賴 **LTE/LTE-CA 行動網路**。
3. **軟體特徵**：主要的耗電 App（如 `u0a274`, `u0a182`）均呈現 **Radio-heavy（行動網路傳輸高）** 的特徵，而非 CPU 背景偷跑或背景鎖喚醒。
