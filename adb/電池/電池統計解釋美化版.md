## 3. Realtime 與 Uptime 的區別

BatteryStats 中 `realtime` 與 `uptime` 的指標定義如下：

* **Realtime**：從統計開始後實際經過的時間（Elapsed Real Time），包含 CPU 運作、螢幕亮起/關閉及 CPU 進入 suspend / sleep 的總和。
* **Uptime**：CPU 未進入 suspend 的累積時間。當手機進入深度睡眠時，`realtime` 增加但 `uptime` 停滯。

```
Realtime
│
├── CPU active ─────────► 計入 Uptime
└── Suspend / Sleep ────► 不計入 Uptime

```

## 13. 最終結論與下一步

1. **網路模組為主要瓶頸**：10 分鐘測試中，螢幕亮起 75.4%，Cellular Radio 高達 **83.2%** 處於 active 狀態。弱訊號、Wi-Fi、GPS、Bluetooth 與 WakeLock 皆已排除為主要誘因。
2. **核心 App**：`org.thunderdog.challegram` 與 `com.brave.browser` 為主要 Radio 耗電來源。
3. **數據限制**：因 `Actual drain = 0 mAh`，無法直接評估實際續航下降速度與電池硬體健康度。

**建議下一步**：
進行一段 **30 分鐘以上的「純螢幕關閉待機測試」** 並重新抓取 BatteryStats，以利排除螢幕使用干擾，精準分離背景 Radio 與 Wakelock 活動。
