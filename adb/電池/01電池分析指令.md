# 📱 Android BatteryStats 耗電分析與測試指南

本指南包含 **BatteryStats 續航測試標準流程**、**ADB 電池分析指令速查表** 以及 **Batterystats AI 提問詞範本**。

---

## 🔋 第一部分：BatteryStats 電池續航測試流程

### 🎯 測試目的
將 BatteryStats 的**統計起點**與**實際放電起點**精準對齊，以獲取最準確的數據分析：
* 實際掉電百分比與每 1% 可使用時間
* 螢幕耗電與待機耗電
* 行動網路 / Wi-Fi 耗電
* 個別 App 耗電佔比

---

### 🔄 標準測試流程

```
[ 1. 充滿 100% ]
       ↓
[ 2. 保持充電狀態 ] ──➔ 執行 dumpsys batterystats --reset
       ↓
[ 3. 確認 level = 100 ]
       ↓
[ 4. 拔掉充電器 ] ─────➔ ⚡ 正式放電與統計起點同步開始
       ↓
[ 5. 開始固定條件測試 ] (固定亮度、網路、操作內容，不中途充電)
       ↓
[ 6. 測試至指定電量 ] (建議至少至 20% 或 10%)
       ↓
[ 7. 匯出 Batterystats 日誌 ]
```

---

### 📝 詳細步驟說明

#### 1. 滿電準備
將手機充滿至 **100%**。
> **原因**：確保每次測試皆從完整電量開始，建立客觀的對照基準。

#### 2. 重置統計資料（保持連接充電器）
```bash
adb shell dumpsys batterystats --reset
```
> **原因**：清除舊有的累積數據，讓統計歸零。

#### 3. 確認電池狀態
```bash
adb shell dumpsys battery
```
確認輸出結果包含：
```yaml
level: 100
```
> **原因**：確認 Reset 後、正式放電前仍然保持滿電狀態。

#### 4. 拔除充電器
> ⚡ **關鍵點**：從拔線的這一刻起，正式進入測試期。「實際放電」與「BatteryStats 統計」達成完全同步。

#### 5. 執行固定條件測試
例如測試 Brave 瀏覽器：
* 固定螢幕亮度（建議固定百分比或關閉自動亮度）
* 固定網路條件（純 Wi-Fi 或純行動網路）
* 固定測試腳本 / 操作內容
* **禁止中途充電或再次執行 `--reset`**

#### 6. 測試至指定剩餘電量
建議至少測試至 **20%** 或 **10%**。
> **原因**：放電時間越長，平均耗電率與數據取樣越具參考價值。

#### 7. 匯出分析日誌
測試結束後立即抓取統計資料：
```bash
adb shell dumpsys batterystats > batterystats.txt
```
*建議同步記錄測試時間軸，例如：`[時間, 電量, 溫度, 電壓]`。*

---

### ⚠️ 測試注意事項

| 類別 | 操作方式 | 影響說明 |
| :--- | :--- | :--- |
| ✅ **最佳做法** | **充滿 ➔ 保持充電 ➔ Reset ➔ 確認 100% ➔ 拔電 ➔ 測試** | 統計數據與實際放電 100% 對齊，數據最精確。 |
| ❌ **不建議作法** | 100% ➔ 拔電 ➔ 使用一段時間（如掉至 95%）➔ 才執行 `--reset` | Reset 會抹除前面 5% 的紀錄， BatteryStats 僅能抓取 95% 之後的資料，無法呈現完整放電週期。 |

## 🛠️ 第二部分：Android 耗電與定時器分析指令速查表

> 💡 **事前準備**：執行以下指令前，請確保手機已透過 ADB 與電腦連結。部分高級指令需要 root 權限。

### 1. 🔋 電池數據基礎管理與匯出

* **重置統計歷史**
  ```bash
  adb shell dumpsys batterystats --reset
  ```
  *用途：清除舊數據。建議在 100% 滿電拔線時立刻執行。*

* **匯出完整電池報告**
  ```bash
  adb shell dumpsys batterystats > battery.txt
  ```
  *用途：傾印完整的電池狀態報告（內容達數萬行，建議輸出為 `.txt` 檢視）。*

* **僅匯出歷史時間軸（History）**
  ```bash
  adb shell dumpsys batterystats --history > battery_history.txt
  ```
  *用途：記錄螢幕開關、網路切換、掉電時間點，適合追查異常掉電的精確時刻。*

* **匯出 Battery Historian 專用格式（Checkin）**
  ```bash
  adb shell dumpsys batterystats --checkin > batterystats.csv
  ```
  *用途：以 CSV 格式輸出，專門用於匯入 Google 官方 **Battery Historian** 圖形化分析工具。*

---

### 2. 🔍 電池數據精準過濾（使用 sed / grep / awk）

* **擷取核心硬體與網路能耗摘要**
  ```bash
  adb shell dumpsys batterystats | sed -n '/Statistics since last charge:/,/CONNECTIVITY POWER SUMMARY END/p'
  ```
  *用途：過濾個別 App，直接呈現螢幕、Wi-Fi、行動網路等整體能耗比例。*

* **擴大擷取範圍至喚醒原因（All wakeup reasons）**
  ```bash
  adb shell dumpsys batterystats | awk '
    /Statistics since last charge:/ { flag=1 }
    /All wakeup reasons:/ { in_wakeup=1 }
    flag {
      if (in_wakeup && !/^ / && !/All wakeup reasons:/) { flag=0 }
      else { print }
    }
  '
  ```

* **快速檢視健康度、放電率與亮屏時間**
  ```bash
  adb shell dumpsys batterystats | egrep -i "capacity|discharge|idling|wakelock time|Screen on:"
  ```
  *參數說明：*
  * `capacity`：電池設計容量與當前估算容量
  * `discharge`：放電速率
  * `Screen on`：亮屏時間（SoT），用於比對放電合理性

* **檢查休眠與閒置狀態**
  ```bash
  adb shell dumpsys batterystats | grep -Ei "idling|suspend"
  ```
  *用途：確認熄屏後系統是否順利進入 **Doze 模式** 或 **Suspend（掛起）**。若數值過低，代表背景持續被喚醒。*

---

### 3. ⏰ 定時器與背景喚醒追查

* **查詢持有中的 Wake Locks（喚醒鎖）**
  ```bash
  adb shell dumpsys power | grep -A 10 "Wake Locks:"
  ```
  *用途：當熄屏後 CPU 無法進入深層休眠時，查看是哪些 App 持有 Wakelock 阻止系統休眠。*

* **統計第三方 App 定時器觸發 Top 20**
  ```bash
  adb shell dumpsys alarm | grep -E "numAlarms|u0a" | sort -nr | head -n 20
  ```
  *用途：排查背景喚醒最頻繁的 App（UID 為 `u0a` 開頭）。`numAlarms` 數值越高，代表將系統拉起休眠的次數越多。*

* **查詢桌面小工具與定時更新排程**
  ```bash
  adb shell dumpsys alarm | grep -Ei "appwidget|update" -A 2
  ```
  *用途：找出因過度頻繁更新（如每 5 分鐘刷一次天氣/新聞）而導致無法深層休眠的定時器。*

## 🤖 第三部分：Batterystats AI 分析提問詞範本

將分析日誌貼給 AI 時，可搭配以下 Prompt 範本獲取結構化的診斷報告。

---

### 📋 範本一：全方位深度診斷（推薦）

```text
請幫我分析以下這段 Android 系統的 `batterystats`（電池統計數據）日誌檔。

請依序幫我拆解並回答以下四個部分：

1. 核心數據總覽與換算：
   - 估計電池容量是多少 mAh？
   - 這次統計總共歷時多久？總共消耗了多少 mAh？換算大約扣了百分之幾的電量？
   - 螢幕開啟時間（SoT）與螢幕關閉（待機）時間各是多少？

2. 精算每小時耗電率（% / h）：
   - 請根據總容量與消耗的 mAh，精確計算出「螢幕開啟耗電率（% / h）」與「螢幕關閉待機耗電率（% / h）」。
   - 請簡評這個耗電數據屬於「極佳、正常、還是偏高」？

3. 耗電黑手與異常分析：
   - 檢查日誌中的「Wakelock（喚醒鎖定）」、「Wakeups（強制喚醒次數）」與「Alarms（定時器觸發）」。
   - 揪出背景活動最頻繁、最可能導致耗電的系統組件或 App，並解釋它們為什麼在背景活動。

4. 具體優化建議：
   - 針對抓出來的耗電黑手，提供實用的排查與改善步驟。

【備註資訊】：
- 手機型號：（例如：Samsung Galaxy S23 / Google Pixel 8）
- 測試情境：（例如：純 Wi-Fi 播放 YouTube 3 小時）

【以下為我的日誌數據】：
（請在此處貼上您的 Batterystats 數據）
```

### ⚡ 範本二：極簡速查版

```text
這是我手機的 Android 電池統計日誌。請直接用條列式、精簡短句幫我定檢：

1. 算出「螢幕開啟」和「螢幕關閉（待機）」的【每小時耗電 % / h】。

3. 直接點名哪幾個 App 或系統組件的 Wakelock/Wakeups/Alarms 數據異常偏高？
4. 給出 2~3 個最直接的省電優化動作。

【以下為日誌數據】：
（請在此處貼上您的 Batterystats 數據）
```

---

### 💡 AI 分析小技巧
* **保留關鍵欄位**：複製日誌時，請務必保留 `Screen on:`、`Total full wakelock time:` 及結尾處各 Package（如 `com.google.android.gms`）的細節，能大幅提升 AI 比對精準度。
* **補充機型資訊**：在 Prompt 中加上手機型號，AI 對於原廠專屬服務（如 Samsung GOS、Xiaomi MIUI/HyperOS 背景服務）的剖析會更加到位。
