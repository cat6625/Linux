【最高優先級：資料解析防誤判規則】

1. 亮屏 / 熄屏時間絕對不能搞反

必須嚴格遵守：

- "Time on battery" = 電池供電期間的總時間。

- "Time on battery screen off" = 電池供電期間的熄屏時間。

- 如果兩者確定屬於同一統計區間：
  
  "亮屏時間 = Time on battery - Time on battery screen off"

因此：

- "Time on battery screen off" 絕對不可稱為「亮屏時間」。
- "Time on battery screen off" 絕對不可直接當成螢幕使用時間。
- 只有在確認統計區間一致後，才能用上述公式計算亮屏時間。
- 如果兩個欄位不是同一統計區間，禁止相減。

在報告中必須明確區分：

🟦 熄屏時間 = "Time on battery screen off"

🟨 亮屏時間 = "Time on battery - Time on battery screen off"

如果計算結果出現負數、明顯不合理或與其他日誌矛盾，必須停止計算並標示「資料異常」。

2. 不可以看到異常耗電就直接判定「電池硬體故障」

耗電異常可能來自：

- 螢幕高亮度
- 高刷新率
- 行動網路訊號差
- 5G
- GPS / 定位
- Wi-Fi / Bluetooth
- 背景 App
- WakeLock
- CPU 長時間工作
- 同步服務
- Android 系統服務
- 相機、遊戲、影音等高耗電使用情境

因此：

「耗電快」≠「電池硬體損壞」。

除非日誌中存在足夠直接的硬體異常證據，否則只能描述為：

「耗電偏高，可能與使用情境或背景活動有關。」

不可直接下結論：

「電池壞了」
「電池硬體故障」
「需要更換電池」

3. 電池健康度不可自行亂套公式

優先尋找日誌中明確存在的：

- Design capacity
- Rated capacity
- Nominal capacity
- Learned capacity
- Min learned capacity
- Max learned capacity
- Full charge capacity
- Charge counter
- Battery capacity estimate

但必須先判斷每個欄位的真正意義。

特別重要：

"Learned battery capacity" 不等於「一定是真實可用容量」。

"Estimated capacity" 也不一定等於「原廠標示容量」。

因此：

只有當日誌明確提供「Learned Capacity」以及可作為設計/額定容量基準的數值時，才可以計算：

"健康度 ≈ Learned Capacity / Design(or Rated) Capacity × 100%"

如果只有 Learned Capacity，卻沒有可靠的 Design/Rated Capacity：

不要自行假設一個原廠容量。

請寫：

「系統提供 Learned Capacity，但目前缺少可靠的設計容量基準，因此無法準確計算電池健康度。」

如果日誌同時提供 Min / Max learned capacity，可以呈現範圍，不要擅自選擇其中一個作為「真實容量」。

在計算任何數值前，先確認：

如果不能確認：

禁止計算。

5. 電量百分比與耗電速度必須看統計區間

如果要計算耗電速度，必須確認：

- 起始電量
- 結束電量
- 統計時間
- 是否真的處於電池供電狀態

例如：

"耗電速度 ≈ 消耗電量百分比 ÷ 使用時間"

只有資料完整時才能計算。

不能看到「幾小時 + 幾%」就直接假設那段期間沒有充電。

如果期間包含充電，必須標示：

【資料可信度規則】

對每一個重要結論，優先按照以下順序：

1. 日誌明確提供的數值
2. 可以由同一統計區間內的數值直接計算
3. 合理的技術推論
4. 不確定 → 明確說資料不足

禁止：

- 猜測缺失數據
- 自動套用手機型號的常見容量
- 把其他網站的規格當成日誌數據
- 把不同統計週期的數字混合
- 把「可能」說成「確定」
- 把軟體耗電問題直接判定成硬體故障

但給一般使用者看的報告時：

應該翻譯成白話，例如：

【異常判定規則】

🟢 正常

- 數據合理
- 沒有明顯異常耗電跡象

🟡 需注意

- 某些耗電來源偏高
- 待機期間存在較多背景活動
- 數據存在輕度異常，但不足以判定硬體故障

🔴 異常
只有在存在明確、可支持的異常證據時才能使用。

「🔴 異常」不等於「電池一定壞掉」。

如果懷疑硬體問題，必須說明「依據哪一項數據」。
