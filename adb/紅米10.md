列出使用者安裝套件==>
adb shell pm list packages -3

列出已停用套件==>
adb shell pm list packages -d

列出已反安裝套件==>
comm -13 <(adb shell pm list packages | sort) <(adb shell pm list packages -u | sort)

指令原理拆解adb shell pm list packages | sort：取得目前手機中「正常安裝/啟用中」的所有套件並排序。adb shell pm list packages -u | sort：取得手機中「所有套件（含已反安裝但留有本體暫存的）」並排序。comm -13：這是 Linux 非常強大的文字比對指令。-13 代表「隱藏只在第一個清單出現的行」以及「隱藏兩個清單重複的行」，最後只輸出「僅在第二個清單（也就是多了已反安裝套件的清單）才有的內容」

## 🔋 為什麼「直接刪除系統服務」反而可能造成耗電？

這是 Android 底層常見的「異常耗電迴圈（Retry Loops）」現象：

1.  喚醒鎖（Wakelock）被卡死：小米系統中的許多核心組件（如安全中心、桌面）被寫死了定時檢查機制。當你強行移除 com.miui.analytics 或 com.miui.msa.global 後，這些組件在背景會因為「找不到目標檔案」而陷入瘋狂重試的死循環。
    
2.  CPU 無法休眠：這種死循環會產生大量的錯誤日誌（Error Logs）並不斷寫入系統，導致處理器（CPU）被強制喚醒，無法進入低功耗的「深層休眠（Deep Sleep）」，進而引發手機莫名發燙、待機電量暴跌。
    
3.  安全做法：使用 aShell 的 disable-user（停用）等同於告訴系統「此服務已休眠」，其他組件便會停止發送請求，比直接 uninstall（移除）更不易噴電。
