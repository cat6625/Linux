# 免費 AI 平台能力比較與省額度工作流指南

這份指南彙整了主流免費 AI 平台（Duck.ai、HuggingChat、Claude、ChatGPT）的定位差異、多平台無縫接力策略，以及降低來回修改消耗的單次精準提示詞（Prompt）架構。

---

## 一、 免費 AI 平台規格與能力對比

### 1. 免註冊隱私平台：Duck.ai vs. HuggingChat

| 比較項目 | Duck.ai（免費版） | HuggingChat（訪客模式） |
| :--- | :--- | :--- |
| **可用模型陣容** | 商業輕量版＋高參數開源模型（如 GPT-6 Luna、GPT-5.4 mini、Claude 4.5 Haiku、Gemma 4 31B、Mistral Small 4） | 純開源模型大本營（如 DeepSeek、Qwen、Llama、Mistral 等最新開源權重） |
| **隱私與數據保護** | **極高**。中繼剝除個人 IP 與中繼資料，對話僅存於本地瀏覽器，不供廠商訓練。 | **中等**。訪客對話可能被用於改善開源模型或統計分析，隱私隔離度不如 Duck.ai。 |
| **使用次數限制** | 每日有動態總量上限（官方未公開確切數字，一般日常問答極難觸頂）。 | 訪客模式限制較嚴（通常每日約 10 次請求後會強制要求註冊免費帳號）。 |
| **檔案與多模態** | 支援圖片分析、AI 生圖與 PDF 讀取（免費版上限 15 頁），不支援試算表。 | 支援文件與圖片上傳，並具備開放原始碼的影像生成工具。 |
| **即時連網搜尋** | **無**（僅依賴模型訓練數據，若需搜尋需切回 DuckDuckGo 搜尋頁）。 | **有**（內建 WebSearch 功能，可即時抓取網路最新資訊彙整）。 |

### 2. Claude 免費版核心能力與限制
* **核心優勢**：開放主力模型 **Claude Sonnet** 與輕量模型 **Claude Haiku**，支援 **Artifacts 即時預覽**、連網搜尋、PDF/圖片分析與最多 5 個 **Projects（專案資料夾）**。
* **最大痛點**：採用**滾動式 5 小時算力池**（約為付費 Pro 版的 1/5 用量）。短對話約可傳送 15～40 則訊息；若上傳大檔案或在同視窗長篇追問，約 5～10 句就會達到上限並需等待冷卻。

## 二、 延長 Claude 免費額度的 5 個核心技巧

Claude 每次送出新訊息時，都會將「該視窗內從第一句到最新一句的所有歷史紀錄與附件」重新讀取一遍。掌握此機制即可大幅延長可用時間：

1. **勤開新對話（New Chat）**：完成單一小任務或切換主題時立刻開新視窗。若需延續進度，先請 Claude 用 200 字總結現況，再將摘要貼入新視窗繼續。
2. **簡單任務手動切換「Haiku」**：翻譯、錯字檢查、信件潤飾等基礎任務手動切換為輕量模型 **Haiku**，把珍貴的 **Sonnet** 額度留給寫程式與複雜分析。
3. **檔案先瘦身，用「編輯（Edit）」代替追問**：上傳 PDF 前先擷取關鍵頁數；若發現指令沒下好，點擊上一則訊息右下角的**「編輯」圖示**直接修改重送，避免無效對話佔用上下文。
4. **善用「專案（Projects）」管理背景資料**：針對固定任務建立專屬 Project 並設定簡短指令，但避免塞入用不到的龐大參考檔。
5. **關閉非必要連網與限制輸出字數**：不需要查最新資訊時關閉 Web Search，並在指令末尾加上「條列重點回答，字數控制在 300 字以內」。

## 三、 多平台免費額度輪替策略（全天候無痛工作流）

透過「任務分流＋摘要接力」，可在不付費的情況下全天候順暢作業：

* **ChatGPT（前線蒐集部隊）**：利用其寬鬆額度與連網功能，負責**前期資料蒐集、即時網路查詢、長文初稿發想與文件初步摘要**。
* **Duck.ai（無限量隱私備援庫）**：負責**機密草稿去識別化、瑣碎翻譯潤飾**，以及當 Claude 和 ChatGPT 都在冷卻時的無縫替補。
* **Claude（精密外科手術刀）**：將前兩者整理好的精華草稿貼入 Claude，只用於**最終商業定稿、複雜程式除錯與 Artifacts 前端視覺化**（通常 1～2 則訊息即可結案）。

## 四、 高效率單次提示詞（Prompt）範本庫

### 1. Duck.ai 輕量模型「高精準自訂指令」
將以下規則填入 Duck.ai 的 **Customize（系統提示詞）** 中，可彌補輕量模型容易籠統的缺點：

> 1. **語言與格式**：永遠使用「繁體中文（台灣習慣用語）」回答。優先使用條列式重點與粗體字排版，避免長篇大論。
> 2. **思考與精準度**：回答前請先在內部釐清邏輯。遇到不確定或缺乏最新資料的問題，請直接說「我不確定」，絕對不要編造事實。
> 3. **直接切入重點**：省略「你好」、「這是一個很好的問題」等客套開場白，第一句話直接給出核心結論。

### 2. 萬用單次精準公式（R-T-C-F 架構）
**【角色 Role】＋【具體任務 Task】＋【背景限制 Constraints】＋【輸出格式 Format】**
* **必備防呆結尾句**：「如果我的資訊有缺漏，請先列出 3 個關鍵問題問我，確認後再開始執行。請省略解釋與寒暄，直接輸出最終結果。」

### 3. 寫程式：新功能開發專用範本

> 你是一位精通「**[填入語言/框架，如：Python 3.11 / React 19]**」的資深軟體架構師。請幫我實作以下功能：
> 
> 1. **核心需求**：[用一句話描述功能]
> 2. **輸入與輸出**：輸入為 [資料型態與格式]；輸出為 [預期回傳值與檔案格式]。
> 3. **技術限制與防呆**：
>    * 僅使用標準函式庫或主流穩定套件（請明確列出需安裝的套件指令）。
>    * 必須包含完整的錯誤處理（Try-Catch）與邊界條件檢查（如網路超時、空值）。
>    * 程式碼需具備清晰的型別註解與關鍵邏輯的繁體中文註解。
> 4. **輸出格式要求**：
>    * **省略原理長篇大論與客套話**，直接提供「完整、可直接複製執行的程式碼」以及「1 組簡單的測試範例」。
>    * 若需求有邏輯矛盾或資訊不足，請先列出 3 個確認問題，先不要寫程式。

### 4. 寫程式：精準除錯（Debugging）專用範本

> 請幫我針對以下程式錯誤進行深度除錯。請先分析根本原因，再提供修復方案：
> 
> 1. **執行環境**：[例如：Windows 11 / Docker / Python 3.10]
> 2. **預期行為**：[這段程式原本應該做到什麼事]
> 3. **實際行為與完整報錯訊息（Error Log）**：
> ```text
> [在此貼上完整的錯誤堆疊訊息]
> ```
> 4. **相關程式碼片段**：
> ```[填入語言]
> [在此貼上出錯函式與前後相關的程式碼]
> ```
> 5. **修復限制與輸出要求**：
>    * 嚴禁隨意更動未報錯的既有變數名稱與外部介面結構。
>    * 請依序輸出：**① 錯誤根本原因（限 3 句話內說明）**、**② 修改後的完整函式程式碼（在修改處加上 `// [FIX]` 註解標示）**、**③ 預防此類錯誤的簡短建議**。
>    * 省略寒暄，直接給出結構化結果。

> **💡 修改大檔案時的省額度密技**：在追問修改時加上一句「**請只輸出有修改的函式區塊，其餘未變動的部分用 `// ... existing code ...` 省略即可**」，可省下約 70% 的輸出算力消耗。
