## BatteryStats 電池續航測試流程
目的

讓 BatteryStats 的統計起點與實際電池放電起點一致，方便準確分析：

實際掉電百分比
每 1% 可使用多久
螢幕耗電
行動網路耗電
App 耗電
待機耗電
測試步驟
1. 先將手機充滿至 100%

原因：
確保測試從完整電量開始，方便比較不同次測試的續航表現。

2. 保持充電器連接，執行 BatteryStats Reset
adb shell dumpsys batterystats --reset


原因：
清除之前累積的 BatteryStats 資料，讓新的統計從這次測試開始。

3. 確認電量仍為 100%
adb shell dumpsys battery


確認：

level: 100


原因：
確認 Reset 後、正式放電前仍然是滿電，避免測試起點不明確。

4. 拔掉充電器

這一刻開始正式計算續航。

即：

100% → 拔掉充電器 → 開始測試


原因：
此時「實際放電開始」和「BatteryStats 統計開始」幾乎完全對齊。

5. 開始固定條件的測試

例如測試 Brave：

固定螢幕亮度
固定 Wi-Fi / 行動網路條件
固定測試內容
不中途充電
不再次執行 --reset
盡量不要改變測試環境

原因：
避免不同測試條件造成耗電差異，讓結果可以比較。

6. 測試到指定電量

建議至少測到：

20% 或 10%


原因：
測試時間越長，平均耗電率越有參考價值。

7. 測試結束後再抓 BatteryStats
adb shell dumpsys batterystats > batterystats.txt


同時保留電量紀錄，例如：

時間,電量,溫度,電壓


原因：
BatteryStats 可以分析「誰在耗電」，而電量紀錄可以確認「實際掉了多少電」。

最重要的順序
充滿 100%
    ↓
保持充電
    ↓
dumpsys batterystats --reset
    ↓
確認 level = 100
    ↓
拔掉充電器
    ↓
開始測試
    ↓
20% / 10%
    ↓
抓取 batterystats

不建議
100%
 ↓
拔充電器
 ↓
使用一段時間
 ↓
才執行 --reset


原因：
Reset 會把前面的 BatteryStats 統計清掉。假設已經從 100% 掉到 95% 才 Reset，那 BatteryStats 就只會看到 95% 之後的資料，無法完整對應整個 100% → 20% 的測試。

最佳做法：充滿 → 保持充電 → Reset → 確認 100% → 拔電 → 測試。

# Android 耗電與定時器分析指令速查表

在執行以下指令前，建議先確保手機已透過 ADB 連接電腦。部分指令需要 root 權限或在特定狀態下執行才能取得最佳數據。

---

## 🔋 電池數據基礎管理與匯出

## dumpsys batterystats --reset
* **用途**：清除手機目前累積的電池統計歷史紀錄。
* **補充**：建議在手機剛充滿電（100%）並拔除充電線時立刻執行此指令，這樣後續抓取的數據才會是最乾淨、最準確的「單次放電週期」資料。

## dumpsys batterystats
* **用途**：傾印（Dump）系統完整的電池使用狀態報告。
* **補充**：此指令輸出的文字量極大（通常達數萬行），包含所有硬體與 App 的詳細能耗，強烈建議匯出成檔案檢視（例如：`adb shell dumpsys batterystats > battery.txt`）。

## dumpsys batterystats --history
* **用途**：僅輸出電池狀態的「歷史時間軸」紀錄。
* **補充**：內容包含螢幕開關、網路切換、電量百分比下降的精確時間點。非常適合用來追查手機在「哪一個特定時間點」開始出現異常掉電。

## dumpsys batterystats --checkin
* **用途**：以機器可讀的 CSV 逗號分隔格式，輸出精簡的電池統計數據。
* **補充**：這是 Google 官方耗電分析工具 Battery Historian 所指定的輸入格式。若要進行圖形化網頁分析，必須使用此指令匯出檔案（例如：`adb shell dumpsys batterystats --checkin > batterystats.csv`）。

---

## 🔍 電池數據精準過濾（使用 sed / grep）

## dumpsys batterystats | sed -n '/Statistics since last charge:/,/CONNECTIVITY POWER SUMMARY END/p'
* **用途**：精確擷取自最後一次充電後，核心硬體與網路通訊的能耗精華摘要。
* **補充**：過濾掉冗長的個別 App 細節，直接呈現螢幕、Wi-Fi、行動網路等大項目的耗電佔比，是快速掌握耗電大戶的首選指令。

## 進階版擴大截取範圍到All wakeup reason

dumpsys batterystats | awk '
  /Statistics since last charge:/ { flag=1 }
  /All wakeup reasons:/ { in_wakeup=1 }
  flag {
    if (in_wakeup && !/^ / && !/All wakeup reasons:/) { flag=0 }
    else { print }
  }
'

## dumpsys batterystats | egrep -i "capacity|discharge|idling|wakelock time|Screen on:"
* **用途**：一次打包手機的健康度、放電速度、休眠狀態與螢幕開啟時間。
* **補充**：
  * `capacity`：查看電池設計容量與當前估算容量。
  * `discharge`：檢視放電速率。
  * `Screen on`：亮屏時間，用來對照總放電量是否合理。

## dumpsys batterystats | grep -Ei "idling|suspend"
* **用途**：檢查手機核心的休眠與閒置狀態。
* **補充**：專門用來確認手機在螢幕熄滅後，有沒有正常進入 DeviceIdle（Doze 模式）或 suspend（系統掛起）狀態。如果數值極低，代表手機一直被背景程式喚醒。

---

## ⏰ 定時器與背景喚醒追查

## dumpsys power | grep -A 10 "Wake Locks:"
* **用途**：查詢電源管理器（Power Manager）目前正在持有的 Wake Locks（喚醒鎖）列表與細節。
* **補充**：當螢幕熄滅後 CPU 仍無法進入深層休眠，通常是有 App 持續持有喚醒鎖（例如背景播放、定位或資料同步）。此指令能快速檢視當前有哪些喚醒鎖正在阻止系統休眠。

## dumpsys alarm | grep -E "numAlarms|u0a" | sort -nr | head -n 20
* **用途**：統計並依觸發次數由高到低排序各個第三方 App（UID 通常為 `u0a` 開頭）的定時鬧鐘（Alarm）喚醒數量，並輸出前 20 名。
* **補充**：能快速找出背景喚醒最頻繁的「鬧鐘大戶」。`numAlarms` 代表喚醒次數，數值越高表示該 App 越常將系統從休眠狀態拉起。

## dumpsys alarm | grep -Ei "appwidget|update" -A 2
* **用途**：查詢系統定時器（Alarm）中，與桌面小工具（appwidget）或「定時更新（update）」相關的排程，並顯示匹配行後 2 行（-A 2）的詳細內容。
* **補充**：很多 App 會設定過於頻繁的定時器（例如每 5 分鐘更新一次天氣或新聞），這會導致手機無法深層休眠。此指令能直接抓出是哪一個 App 在頻繁發送喚醒鬧鐘。
