不一定需要 `System.err`，要看卡在哪一步。

## 何時要抓 `System.err`

| 現象 | 要不要 System.err | 重點 tag |
|------|-------------------|----------|
| 解碼失敗、一直 `parse:1`、unable to **parse** url | 可加，有時會有 OkHttp/JSON 例外 | `TV-player`、`postProtobuf` |
| 已是 `parse:0` + 有直鏈，但播不起來 / 一直轉圈 | **通常不用** | `TV-player`、`ExoPlayer`、`Media3` |
| App 閃退、Native crash | 要 | `AndroidRuntime`、`FATAL`、`System.err` |

你現在 JS 解碼已能回 `parse:0`，多數「無法播放」是**播放器吃直鏈**的問題，不是爬蟲例外。

---

## 建議指令（依目的）

**1. 只查爬蟲有沒有解出網址（夠用、比較乾淨）：**

```bash
sudo waydroid shell -- logcat -c
sudo waydroid shell -- logcat -v time | grep --line-buffered -iE \
  'TV-player|TV-detail|TV-t30|postProtobuf|decodeUrl' | tee fongmi.txt
```

看 `TV-player` 回傳是：
- `"parse":0,"url":"https://..."` → 解碼成功，問題在播放
- `"parse":1,"url":".../play/..."` → 解碼仍失敗，再加 `System.err`

**2. 解碼成功但仍播不了（查播放器）：**

```bash
sudo waydroid shell -- logcat -c
sudo waydroid shell -- logcat -v time | grep --line-buffered -iE \
  'TV-player|ExoPlayer|Media3|LoadError|Source error|HTTP|403|404|Unable' | tee fongmi-play.txt
```

**3. 全面抓（含 System.err，log 會很雜）：**

```bash
sudo waydroid shell -- logcat -c
sudo waydroid shell -- logcat -v time | grep --line-buffered -iE \
  'TV-|postProtobuf|decodeUrl|ExoPlayer|Media3|System\.err|AndroidRuntime' | tee fongmi-full.txt
```

你貼的那條可以留著當「全面版」，但日常先用 **1** 或 **2** 較好查。

---

## 快速判斷

打開 `fongmi.txt` 搜尋最後一次點播放：

1. 有 `"parse":0` 且 `url` 是 `http...` → 爬蟲 OK，換線路或查 ExoPlayer  
2. 只有 `"parse":1` 且 url 是 `/play/xxx#sid=` → 還在解碼失敗，才需要 `System.err` + `postProtobuf`  

**結論：** 查「無法播放」不必一開始就抓 `System.err`；先確認 `TV-player` 是 `parse:0` 還是 `parse:1` 即可。
